1. Source Overview and Precedence

Primary Apple Health

GPS runs, swim sessions, walks, resting HR, HRV, sleep. Most complete for cardio with GPS. Must be manually exported from iPhone. Stops updating until re-exported.

Primary Technogym

Indoor cycling power, cadence, calories. Machine strength sessions. Coverage starts Oct 2025. Re-export monthly via GDPR download.

Supplement Schedule Tab

Manual session logs entered directly in the app. Tagged ManualSchedule. Stored in Supabase. Never double-counts against imported data.

Derived Canonical JSON

Output of the pipeline. Apple and Technogym sessions matched by time overlap, deduplicated, merged. This is what the app reads.

Conflict rule: when Apple Health and Technogym both recorded the same session, Technogym wins for power and cadence; Apple Health wins for HR and GPS distance.

2. Apple Health Export and Import

Export from iPhone

1
Open the Health appTap your profile photo in the top-right corner
2
Export All Health DataScroll to the bottom of the profile screen and tap "Export All Health Data". Confirm. This takes 1 to 3 minutes.
3
Share the ZIPAirDrop to your Mac, or save to iCloud Drive / Files. The file is named export.zip (~50 to 200 MB).
4
Extract export.xmlUnzip. Inside is apple_health_export/export.xml. This is the file the script reads.

Run the import script

The PowerShell extraction script runs on Windows. If you are on a Mac, a Node.js alternative may be needed. Check scripts/ for a Mac-compatible version.

In your Codespace terminal
# 1. Upload export.xml to your Codespace (drag into file explorer or use scp)
#    Place it at: /workspaces/Fitness/data_source/export.xml

# 2. Run the Apple Health import
cd /workspaces/Fitness
node scripts/import_apple_workouts.mjs

# 3. Verify output
node -e "
const d = require('./public/data/apple_workouts.json')
console.log('Apple sessions:', d.length)

Each re-import is safe. The pipeline deduplicates by session overlap, so re-importing older data does not create duplicate sessions.

5. Deploying to Vercel

Vercel only deploys from Git commits. Changes visible in the Codespace dev preview but not yet committed will NOT appear on the live site.

After any pipeline run or App.jsx update

cd /workspaces/Fitness

# Stage both the data files and any app code changes
git add public/data/ src/App.jsx

# Commit with a descriptive message
git commit -m "data: re-ingest Apple Health + Technogym, rebuild canonical"

# Push — Vercel auto-deploys within ~90 seconds
git push

# Confirm line count if you updated App.jsx
wc -l /workspaces/Fitness/src/App.jsx

Confirm the deploy

1
Check GitHubgithub.com/agvg75/Fitness — confirm your commit appears on the main branch.
2
Check Vercel dashboardvercel.com/dashboard — the deployment should show "Building" then "Ready" within 90 seconds of the push.
3
Hard refresh the live sitePress Cmd+Shift+R (Mac) or Ctrl+Shift+R (Windows) to bypass the browser cache.

8. One-Time Pipeline Fix (Technogym Classification)

Currently all Technogym sessions come through as MachineWorkout with canonical_type: Machine Cardio. The app-level fix (using rpm_avg as a bike signal) catches some sessions, but the permanent fix belongs in import_technogym.mjs.

Find the section in import_technogym.mjs that assigns type or canonical_type to a session. Apply the following classification logic there, replacing or augmenting whatever is currently used.

// Classification logic to add/replace in import_technogym.mjs
// 'session' is one record from indooractivities.json

function classifyTechnogymSession(session) {
  const raw = session.performedData || {}

  // Extract key metrics (field names from Technogym schema)
  const rpmAvg  = raw.pr?.find(p => p.n === "AvgSpeedRpm")?.v ?? null
  const powerAvg = raw.pr?.find(p => p.n === "AvgPower")?.v ?? null
  const distance = raw.pr?.find(p => p.n === "HDistance")?.v ?? null

  // Bike: rpm_avg present means cadence was measured = stationary bike
  if (rpmAvg !== null && rpmAvg !== undefined) return "Cycling"

  // Power without rpm could also be a bike (some sessions only log power)
  if (powerAvg !== null && powerAvg > 0) return "Cycling"

  // If distance is very high relative to duration, likely a bike
  const dur = raw.pr?.find(p => p.n === "Duration")?.v ?? 0
  if (distance && dur && (distance / dur) > 50) return "Cycling" // >50m/min = bike pace

  // Fallback: check the raw activity type string from Technogym
  const rawType = String(session.activityType || session.type || "").toLowerCase()
  if (rawType.includes("cycl") || rawType.includes("bike")) return "Cycling"
  if (rawType.includes("run") || rawType.includes("tread")) return "Running"
  if (rawType.includes("row")) return "Rowing"
  if (rawType.includes("swim")) return "Swimming"
  if (rawType.includes("strength") || rawType.includes("free") || rawType.includes("weight")) {
    return "Traditional Strength Training"
  }

  return "Machine Cardio" // genuine fallback
}

After editing import_technogym.mjs, re-run the full pipeline (Section 4) and push (Section 5). The Cycling volume charts should then show bars for all months with Technogym sessions.
